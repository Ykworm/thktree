# 分支创建与总结流程需求文档

## 概述

本文档描述在 ThkTree 中创建分支时的总结流程设计。核心思想是：当用户从某个节点创建新分支时，先通过一个专门的总结对话页面让用户打磨总结内容，然后将这个总结作为新分支的第一个用户消息。

---

## 1. 核心流程

### 1.1 完整流程图

```
用户点击「创建分支」
    ↓
判断是否有父节点
    ├─ 无父节点（根节点）→ 直接创建新节点，跳转到对话页面
    └─ 有父节点 → 进入总结流程
                    ↓
              读取父节点完整对话历史
                    ↓
              跳转到「总结对话页面」
                    ↓
              用户与 LLM 多轮打磨总结
                    ↓
              用户点击「确认使用此总结」
                    ↓
              创建新分支节点
                    ↓
              将总结内容作为新分支的第一条 user 消息
                    ↓
              跳转到新分支的对话页面
```

### 1.2 触发时机

- **入口**：在主题详情页面，选中某个节点后，点击「创建分支」按钮
- **条件**：仅当选中的节点有父节点时才触发总结流程；创建根节点直接跳过

---

## 2. 总结对话页面

### 2.1 页面功能

这是一个专门的对话页面，用于打磨总结：

| 功能 | 说明 |
|------|------|
| 左侧/顶部 | 显示提示：「请打磨总结内容，确认后将作为新分支的起点」 |
| 对话区域 | 标准的多轮对话界面，用户可以反复修改总结 |
| 底部操作栏 | 包含「取消」和「确认使用此总结」两个按钮 |

### 2.2 初始 prompt

当进入总结页面时，自动发送第一条消息给 LLM，内容为：

```
请帮我总结以下对话的核心内容，要求：
1. 保持关键信息完整
2. 语言简洁清晰
3. 适合作为新对话的上下文

---
[父节点完整对话历史]
```

### 2.3 用户操作

- **取消**：返回上一页面，不创建新分支
- **确认使用此总结**：
  - 将最后一条 assistant 消息的内容作为总结
  - 创建新分支
  - 将该总结作为新分支的第一条 user 消息
  - 跳转到新分支对话页面

---

## 3. 数据流转

### 3.1 父节点对话历史读取

需要从父节点的 `session.md` 中读取完整的对话历史，用于：
1. 生成初始总结 prompt
2. 在总结页面中展示（可选，MVP 可先不做）

### 3.2 新节点创建

当用户确认总结后，执行以下操作：

1. **调用 `createChatNode`** 创建新节点（与现有逻辑一致）
2. **将总结内容作为第一条 user 消息** 写入新节点的 `session.md`
3. **自动触发 LLM 回复**（可选，MVP 可先不做自动触发，让用户手动发送）

### 3.3 新节点的 session.md 结构

```markdown
---
schema: session/v1
themeId: "thm_..."
nodeId: "nd_..."
kind: "chat"
parentId: "nd_父节点ID"
title: "新分支标题"
createdAt: "2026-05-26T12:00:00.000Z"
updatedAt: "2026-05-26T12:00:00.000Z"
---

## user · 2026-05-26T12:00:00.000Z · msg_xxx
[总结内容]
```

## 4. UI/UX 细节

### 4.1 状态提示

- 在总结页面顶部显示：「正在为新分支打磨总结...」
- 确认后显示：「正在创建新分支...」的 loading 状态

### 4.2 导航

- 总结页面应该有独立的路由
- 可以通过左上角返回按钮取消
- 确认后直接跳转到新分支对话页面，不能返回

### 4.3 分支标题

- 创建分支时，用户需要输入分支标题（与现有逻辑一致）
- 标题在进入总结页面前输入，还是在确认后输入？
  - **建议**：在进入总结页面前输入，与现有 `createChildChatNode` 逻辑保持一致

## 7. 边界情况处理

### 7.1 父节点没有对话历史

- 如果父节点的 `session.md` 只有 frontmatter，没有消息
- **处理**：跳过总结流程，直接创建新分支（或提示用户父节点没有对话）

### 7.2 用户在总结页面取消

- **处理**：返回主题详情页面，不创建任何节点

### 7.3 总结页面出错

- **处理**：显示错误提示，允许用户重试或取消

## 附录：问答

### Q: 为什么不直接用 context-summary.md？
A: 这是设计决策，将总结作为第一条 user 消息可以让用户更灵活地修改和补充总结内容，同时简化了存储结构。

### Q: 总结页面和普通对话页面有什么区别？
A: 总结页面有固定的初始 prompt，底部有「确认使用此总结」按钮，确认后会创建新分支。

### Q: 用户可以在总结页面发送多条消息吗？
A: 可以，用户可以与 LLM 多轮对话来打磨总结，最后一条 assistant 消息的内容会被用作总结。
