# ThkTree Jobs-to-Be-Done 分析

> 分析方法：[jobs-to-be-done skill](~/.qoder/skills/jobs-to-be-done/SKILL.md)（Wondelai 出品，基于 Clayton Christensen 框架）
> 分析对象：ThkTree v0.x（iOS-only Flutter app，AI 驱动的深度思维工具）
> 分析日期：2026-06-24
> 当前评分：**5.5 / 10**（详见 § 7 评分矩阵）

---

## 1. Job Statement（核心 job）

> **When** 我在认真思考一个复杂问题/写作/学习某一领域，
> **I want to** 用 AI 帮我把脑中混乱的念头层层展开、并把对话沉淀为可回看可复用的结构化笔记，
> **so I can** 把这次思考真正变成我能带走的认知资产，而不是又一段看完就忘的聊天记录。

### 1.1 检验 job 表述的合规性

| 检验项 | 通过？ | 备注 |
|--------|--------|------|
| 一句话能说完？ | ✓ | 36 词 |
| 没有提及产品名？ | ✓ | 全句无"ThkTree" |
| 包含 circumstance（When）？ | ✓ | "认真思考 / 写作 / 学习" |
| 包含 progress（I want to）？ | ✓ | "层层展开 → 结构化笔记" |
| 包含 outcome（so I can）？ | ✓ | "带走的认知资产" |
| 关注 progress 而非 feature？ | ✓ | 强调"沉淀/带走"，不是"树形/对话" |

### 1.2 反例：bad job statement

❌ "When 我想用 ThkTree 管理我的笔记" —— 把产品名写进去了，把 job 偷换成"用产品"
❌ "When 我想用 AI 写笔记" —— 把 job 偷换成"用工具"，不是"思考"
❌ "When 我想要一个 Markdown 编辑器" —— 太具体（功能），不是 progress

## 2. Three Dimensions（功能 / 情感 / 社交）

> 任何 job 都必须三维完整，缺一不可。

### 2.1 Functional（功能维度）

**用户要做的事：**
- 把一个模糊问题拆成多个可独立探索的子问题（树形分支）
- 与 AI 沿每个分支做多轮对话
- 把对话里对自己有用的片段"剪"出来沉淀成笔记
- 后续能在自己的笔记/对话库中全文检索回这些认知
- 在重新面对相关问题时，能召唤上次对话的"上下文总结"

### 2.2 Emotional（情感维度）

**用户想感受到的：**

| 情感 | 来源 | ThkTree 当前表现 |
|------|------|------------------|
| **沉静** | 不被通知/广告/红点打扰 | ✓ warm-minimal 设计 + 本地优先（强） |
| **掌控感** | 我知道我所有数据在哪、能导出 | ✓ Markdown 文件 + SQLite，可重建（强） |
| **思考的节奏感** | 不被 AI 拽着走，能"停一停" | △ 流式快、stop 按钮有（部分，需要更多"暂停/反思" hook） |
| **创造物的美感** | 像在写一本属于自己的书 | ✓ Cormorant Garamond serif + 典雅黑金调（强） |
| **不被窥视** | 我的思考不喂给别人的模型 | ✓ 自配 API Key + 离线优先（强） |
| **累积的满足感** | 我有一个"知识花园"在长出来 | ◯ 主题树是物理容器，但缺"成长感"的视觉反馈（弱） |

**Emotional 维度评分：7 / 10**（强项是"沉静/掌控/美感"；弱项是"累积满足感"和"反思节奏感"）

### 2.3 Social（社交维度）

**用户希望被如何看待：**

| 社交身份 | ThkTree 当前是否服务 |
|----------|---------------------|
| "我是认真思考的人"（vs 浮浅刷信息） | ✓ 大标题 serif、本地优先设计暗示严肃（强） |
| "我是用 AI 但不被 AI 替代的人"（vs 把思考外包给 ChatGPT） | △ 隐含但未明示（部分） |
| "我拥有自己的知识系统"（vs 用 Notion 在公司模板里） | ◯ 分享功能未闭环，社交属性未建立（弱） |
| "我做了值得分享的思考" | ◯ ShareService + ShareCardWidget 存在但流程未闭环（弱） |

**Social 维度评分：3 / 10**（缺位严重 — 几乎所有社交维度都未明确服务）

### 2.4 三维综合

```
        Functional  Emotional  Social
ThkTree   7/10       7/10      3/10
```

**核心缺失：Social 维度几乎完全没规划** —— 这对一个"个人知识工具"是双刃剑：保护隐私（✓）但也意味着"无法产生口碑传播"（✗）。

## 3. Forces of Progress（进展力四力）

> 决策 = Push（推）+ Pull（拉） vs Habit（惯性）+ Anxiety（焦虑）

### 3.1 Push（推力 — 用户的痛点）

| 痛点 | 强度 | 来源 |
|------|------|------|
| ChatGPT 对话找不到/不持久 | ⭐⭐⭐⭐⭐ | "上次那个 prompt 怎么打的来着" |
| ChatGPT 不能把多分支探索结构化 | ⭐⭐⭐⭐ | "我想让 AI 帮我拆解这个问题" |
| Notion/Obsidian 写笔记是空白页焦虑 | ⭐⭐⭐ | "面对空白页不知从何写起" |
| 公众号/小红书/笔记 App 内容不是"我自己的思考" | ⭐⭐⭐ | "收藏从未打开" |
| 大模型厂商的隐私政策不明 | ⭐⭐⭐⭐ | "我不能用公司数据问 ChatGPT" |
| 思考过程散落在多个 App 里 | ⭐⭐⭐⭐ | "微信文件传输助手 / 备忘录 / Notion / ChatGPT 四处分" |

### 3.2 Pull（拉力 — ThkTree 的吸引力）

| 卖点 | 强度 |
|------|------|
| 树形主题 — 让"分层思考"成为可能 | ⭐⭐⭐⭐⭐ |
| 流式对话 + Markdown 持久化 | ⭐⭐⭐⭐ |
| 本地优先 + 自配 Key — 数据主权 | ⭐⭐⭐⭐⭐ |
| 全文搜索 — 把思考做成"可挖掘的矿" | ⭐⭐⭐⭐ |
| 典雅设计 — 审美共鸣 | ⭐⭐⭐ |
| Face ID 锁 — 思考是私密的 | ⭐⭐⭐ |

### 3.3 Habit（惯性 — 用户的现有习惯）

| 现有习惯 | 切换难度 |
|----------|----------|
| "想思考就用 ChatGPT"（路径依赖） | ⭐⭐⭐⭐⭐（极高 — ChatGPT 是默认入口） |
| "想记笔记就用 Apple Notes/备忘录" | ⭐⭐⭐⭐ |
| "想读文献就用 Notion/Obsidian" | ⭐⭐⭐ |
| "想用 AI 但不想配置 Key" | ⭐⭐⭐⭐（自配 Key 是高门槛） |

### 3.4 Anxiety（焦虑 — 切换阻力）

| 焦虑点 | 严重度 |
|--------|--------|
| "自配 DeepSeek Key 会不会很复杂？" | ⭐⭐⭐⭐（高 — 这是 onboarding 死路） |
| "我的笔记会不会哪天被锁在某个版本里？" | ⭐⭐⭐（中 — 数据导出路径不清晰） |
| "树形结构会不会让我反而要花时间整理？" | ⭐⭐⭐（中 — 结构化是负担也是收益） |
| "用着用着 iOS 升级会不会闪退？" | ⭐⭐（低） |
| "花时间思考/记笔记这件事本身就焦虑" | ⭐⭐⭐⭐（社会层） |

### 3.5 Forces 评分

```
          Push     Pull    Habit    Anxiety
          (推)     (拉)    (惯性)    (焦虑)
强度      5⭐×6    5⭐×2   5⭐×4    5⭐×4
得分      强       中强     极强     强
```

**诊断**：Pull 明显弱于 Habit。这是典型的"小众精品工具"困境 —— 产品做好了，但用户的肌肉记忆更强。

**改进方向**（详见 § 6）：降低 Anxiety 比增加 Pull 优先级更高。

## 4. Big Hire vs Little Hire（两个决策时点）

> 很多产品赢了 Big Hire 却输了 Little Hire（买了不用）。

### 4.1 Big Hire（首次下载/打开决策）

**用户的 Big Hire 时刻**：在 App Store 看到 ThkTree → 下载 → 第一次打开

**Big Hire 的关键障碍**：

| 障碍 | 当前是否有解？ |
|------|----------------|
| 配置 DeepSeek API Key（必须） | ❌ 第一次打开就要求自配 Key，是最大 onboarding 死路 |
| 理解"主题/节点/分支"是什么概念 | ◯ 无引导，靠用户摸索 |
| 第一次对话不知道问什么 | ❌ 无引导/示例 prompt |
| 不知道 AI 思考和自己思考如何分工 | ❌ 未明示 |

**Big Hire 评分：3 / 10**

### 4.2 Little Hire（日常使用决策）

**用户的 Little Hire 时刻**：每天/每周想用 ThkTree 时 → 打开它 → 进入思考

**Little Hire 的关键障碍**：

| 障碍 | 当前是否有解？ |
|------|----------------|
| 上次想到哪了？ | ✓ 主题树 + 节点卡片视觉好 |
| 这次我想思考什么？ | ◯ 没有"今日思考提醒"或"上次未完成的节点"高亮 |
| 打开 ThkTree 会不会很卡？ | ✓ Flutter 流畅度可 |
| 思考完能带走吗？ | ✓ Markdown 导出 |
| Face ID 频繁弹会不会烦？ | ✓ AuthGate 已实现（智能触发） |

**Little Hire 评分：6 / 10**（比 Big Hire 好很多）

### 4.3 关键洞察

> **ThkTree 的 Little Hire 做得不错（核心体验流畅），但 Big Hire 几乎注定失败（onboarding 第一关就卡 Key 配置）**。
>
> 这是典型的"硬核工具"问题 —— 用户必须先投入才有回报，但 onboarding 没给"先尝后买"的空间。

**改进方向**：把"先 5 分钟体验版"（无需配 Key，用本地 mock LLM 或免费额度）作为 Big Hire 第一关，把"配 Key 解锁深度体验"作为后续 step。

## 5. Competitive Landscape（非显性竞争）

> 真正的竞争不是同品类产品，而是"能为同一个 job 提供解决方案的任何东西"。

### 5.1 真正的竞争对手全景

**ThkTree 的 job 是"用 AI 把混乱的思考梳理成结构化认知资产"。能完成这个 job 的所有产品：**

| 类别 | 替代方案 | 替代度 | ThkTree 相对优势 |
|------|----------|--------|------------------|
| **AI 对话工具** | ChatGPT / Claude.ai / Gemini App | ⭐⭐⭐⭐ | ❌ 无持久化、无结构化、无本地化 |
| **AI 笔记** | Notion AI / Obsidian + Copilot | ⭐⭐⭐⭐ | ✓ 树形比 Notion 块更贴思考；✓ 本地优先比 Obsidian 插件更稳 |
| **思维导图+AI** | Miro AI / Whimsical AI | ⭐⭐ | ✓ 比思维导图更文本化，更适合"思考" |
| **手写笔记+AI** | Apple Notes / GoodNotes + AI | ⭐⭐ | ✓ 流式对话 > 涂改重写 |
| **学术/研究 AI** | Elicit / Research Rabbit | ⭐ | ✓ 更通用，不限学术 |
| **日记+AI** | Day One / Reflect | ⭐ | ✓ 更结构化（树 vs 时间线） |
| **代码/技术 AI 笔记** | Cursor / Continue + 工作笔记 | ⭐ | ✓ ThkTree 不限代码 |
| **不做**（非消费） | 用脑子想 / 跟朋友聊 | ⭐⭐⭐⭐ | ❌ 难以结构化、不可回看 |

### 5.2 最危险的"竞品"

**第一竞品：什么都不做**（在脑中想想就过去了）

- 触发条件：用户还没意识到"我可以把思考结构化"
- 占据份额：>70%（绝大多数想法停留在脑子里）
- 攻击策略：**在内容/示例上展示"思考结构化后是什么样"**，让用户看到 target state

**第二竞品：ChatGPT 对话 + 微信收藏**

- 触发条件：用户已经有 ChatGPT 习惯 + 微信文件传输助手
- 占据份额：~15%（年轻用户）
- 攻击策略：**展示"ChatGPT 对话 3 个月后如何找不到"**，制造 Push

### 5.3 隐藏的机会

**ThkTree 没在竞争的、但其实可以做 job 的领域**：

| 领域 | 适配度 | 当前是否做 |
|------|--------|------------|
| 学习/读书笔记 | ⭐⭐⭐⭐⭐ | ◯（功能覆盖但未明示场景） |
| 写作（小说/文章/学术） | ⭐⭐⭐⭐⭐ | ◯（笔记模块可服务但未定位） |
| 决策辅助（"该不该换工作"） | ⭐⭐⭐⭐ | ❌（树形天然适合但未明示） |
| 心理咨询/情绪日记 | ⭐⭐⭐ | ❌（隐私优先是优势但未明确） |
| 教学/备课 | ⭐⭐⭐⭐ | ◯（主题树天然适合） |
| 创业/产品调研 | ⭐⭐⭐⭐ | ❌（竞品分析可做但未明示） |

### 5.4 Competitive Landscape 评分：6 / 10

- ✓ 识别了显性竞品（Notion / Obsidian / ChatGPT）
- ✗ 没识别"非消费"（"用脑子想就完了"）作为第一竞品
- ✗ 没识别"内容场景"作为营销抓手

## 6. Designing for the Job（设计评分）

> 每个产品决策都要回答"这如何帮助用户完成 job？"

### 6.1 ThkTree 的 job 服务度评估

| 产品决策 | 服务的 job 维度 | 评分（0-10） | 改进建议 |
|----------|------------------|--------------|----------|
| 树形主题（嵌套） | Functional：分层思考 | 9 | — |
| 流式对话 + Markdown 持久化 | Functional：沉淀为可回看资产 | 9 | — |
| 本地优先 + 自配 Key | Emotional：掌控感 + 私密 | 9 | — |
| 全文搜索 | Functional：可挖掘的矿 | 8 | — |
| 主题色 5 套循环 | Emotional：归属感 | 7 | — |
| Cormorant Garamond serif | Emotional：文学质感 | 8 | — |
| Face ID 进前台 | Emotional：私密 | 7 | 可能过于频繁弹窗，待验证 |
| 语音播放 | Emotional：可听可读多模态 | 7 | — |
| 节点色（5 套 hash 分配） | Emotional：成长感 | 6 | 同色节点容易混淆 |
| 标题自动建议 | Functional：减少命名负担 | 8 | — |
| iOS 后台中断恢复 | Functional：思考不被中断 | 8 | — |
| 主题/笔记/对话三 tab | Functional：导航清晰 | 6 | 用户可能不知"先建主题还是先建笔记" |
| 分享功能（未闭环） | Social：做值得分享的思考 | 2 | 🔴 优先完成 |
| 笔记图片插入（待开发） | Functional：多模态笔记 | 0 | 🟡 排期中 |
| 节点位置选择器 | Functional：组织笔记 | 6 | — |

### 6.2 缺失的"为 job 设计"环节

**1. 没有"今日该思考什么"的引导**
- 用户每次打开 ThkTree，可能不知道想什么
- 缺失"上次未完成的节点高亮" / "新主题建议" / "近期热点问题"

**2. 没有"思考回顾"机制**
- 笔记/对话多了之后，没人帮忙回顾
- 缺失"你上周思考了 X 个主题，其中 3 个未完成"

**3. 没有"思考的成就感"反馈**
- 缺少"你已经写了 N 万字 / 创建了 N 个主题"的可视化
- 缺少"今天你比昨天多想了 30 分钟"

**4. 没有"思考的社交化"出口**
- 分享未闭环（已知 gap）
- 没有"用 ThkTree 思考后导出为博客/小红书"的模板

## 7. Quick Diagnostic + 0-10 评分

### 7.1 评分矩阵

| 维度 | 当前评分 | 满分 | 达到 10/10 需要什么 |

| 3. Emotional 维度完整 | 7 | 10 | 已服务"沉静/掌控/美感"，缺"反思节奏感/累积满足感" |
| 4. Social 维度完整 | 3 | 10 | 🔴 **严重缺位** — 分享未闭环、社交场景未明示 |

| 8. 访谈过客户的购买时间线 | 0 | 10 | 🔴 **未做用户访谈**（个人项目，无 user base） |

### 7.2 综合评分

```
ThkTree Jobs-to-Be-Done 总评分：5.5 / 10
```

**分数拆解**：
- **产品做对的事**（占 5.5 分）：树形 + 本地优先 + 设计美学 + 工程严谨性
- **产品没做对的事**（缺 4.5 分）：Social 维度、用户访谈、Onboarding、内容场景化

### 7.3 达到 8/10 所需改进（按 ROI 排序）

| 优先级 | 改进项 | 影响维度 | 工作量 |
|--------|--------|----------|--------|
| 🔴 P0 | 分享功能闭环（Social 维度从 3 → 7） | Social + Emotional | 中（已有 ShareService 基础） |
| 🔴 P0 | Onboarding"先 5 分钟体验"流程（不配 Key 也能用 mock LLM） | Big Hire + Anxiety | 中 |
| 🟡 P1 | 用户访谈 10+ 人（购前时间线回顾） | Forces + Discovery | 低（个人项目内做） |
| 🟡 P1 | 内容场景化（"用 ThkTree 写作/学习/决策"模板） | Forces + 营销 | 低 |
| 🟡 P1 | "思考回顾"机制（每周回顾未完成节点） | Little Hire + Emotional | 中 |
| 🟢 P2 | "思考累积"可视化（字数/主题数/月度对比） | Emotional | 低 |
| 🟢 P2 | 导出 Markdown 到博客/小红书模板 | Social | 中 |

## 8. 总结：ThkTree 的核心矛盾

> **ThkTree 在工程深度和设计美学上做到了 9/10，但在"被用户找到、被用户开始、被用户分享"上做到了 3/10。**

这是一个**"产品先于分发"的典型精品项目**：
- ✓ 解决了一个真实的深井 job（深度思考 + 结构化沉淀）
- ✓ 做出了让"认真的人"会心动的设计
- ✗ 没有 onboarding 让"第一次来的人"留下
- ✗ 没有 social 出口让"用得好的人"分享
- ✗ 没有内容场景让"潜在的人"知道这工具存在

**如果只做一件事**：**把分享功能闭环 + Onboarding"先体验"流程**。这两件事会让 5.5/10 → 7/10。
