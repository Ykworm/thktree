# 导出/备份 + 导入恢复 方案讨论

> 状态：brainstorming 阶段，待用户回答 5 个问题
> 来源：REQUIREMENTS.md §13.2 中优先级

---

## 需求锚点

> | 导出/备份 | zip + manifest → 分享面板，目录树结构人类可读 |
> | 导入恢复 | zip → manifest → 恢复到 app（round-trip） |

## 已有上下文

- 记忆：项目支持导出 zip 包，内含 `thktree-manifest.json`，记录 themeId/nodeId/noteId 与人类可读目录名的映射；导入时通过 manifest 精确还原，提供 ID 冲突策略
- 存储层：Markdown 正文 + SQLite 索引（ADR-004），SQLite 可随时从磁盘重建
- 现有 ShareService：仅做单条消息图片分享，不涉及数据导出

## 待确认的 5 个问题

### 1. 导出范围

- **方案 A**：仅全量导出 ✅ 用户选择
- **方案 B**：仅单主题导出
- **方案 C（建议）**：两者都支持 — 设置页"全量备份"，主题详情页"导出此主题"

**决策**：采用方案 A，仅支持全量导出。理由：简化实现，避免单主题导出的复杂性（如跨主题引用、笔记关联等）

### 2. manifest 设计

```json
{
  "schema": "thktree-manifest/v1",
  "appVersion": "1.2.3",
  "exportedAt": "2026-06-18T12:00:00.000Z",
  "scope": "full",
  "themes": [
    {
      "themeId": "thm_01J8...",
      "title": "Swift 学习",
      "dirName": "swift-xue-xi",
      "nodes": [...],
      "notes": [...]
    }
  ]
}
```

**待确认**：
- manifest 要不要包含消息摘要（msgCount / 最后时间）用于导入前预览？
- 目录名 slug 规则：拼音？英文？直接 title（中文有编码风险）？

### 3. 冲突策略

| 冲突类型 | 可能性 | 建议策略 |
|---------|--------|---------|
| themeId 已存在 | 低（ULID） | 跳过 or 重命名 |
| nodeId 已存在 | 极低 | 跳过 |
| title 重复 | 高 | 加"副本"后缀（macOS 标准做法） |

**建议**：智能合并为默认（相同 ID 跳过，title 重复加"副本"）

### 4. 导出入口

- 设置页 → "备份与恢复"（全量备份 + 从 zip 恢复）
- 主题详情页 → "导出为主题包"（单主题导出）
- 导出后走 iOS 系统分享面板（AirDrop / Files / 微信）

### 5. round-trip 保证

**严格保证**：导出 → 导入 → 再导出，两次 zip 完全一致（除 timestamps）
- 导入时 ID 原样保留，不重新生成
- 文件内容不做清洗/优化
- 目录结构精确还原
