## 1. Problem（问题）

> 用户要解决的"痛苦"是什么？痛得有多深？频率多高？

**已知 ✓**：用户想把一次深度思考（对话）真正沉淀为可回看、可复用、可积累的认知资产，而不是"聊完就忘"。

**已知 ✓**：现有方案的"替代/凑合"做法 — 用户其实已经在用以下低配方案：
- ChatGPT/Claude 单聊 → 完事就关窗口
- Obsidian 手动写 → 太慢、需要自己组织
- Notion + 笔记 → 重型协作工具，不适合个人思考
- 微信/Notion 收藏 → 杂乱无章，无法检索

**假设 ⚠️**：这个痛苦**足够深**到让用户切换习惯。证据：
- ✓ 当前 AI 工具用户基数大 → 痛点候选池大
- ✗ 没人明确说"我需要树形对话" → 这是**我们的解决方案假设**，不是问题验证
- ✗ 实际行为数据 → 未上线，无数据

**未知 ✗**：
- 用户**实际**用 ChatGPT/Claude 时，多大比例是"思考型"而非"任务型"？
- 这群"思考型"用户的痛点是"没沉淀"，还是"沉淀太慢"？
- 频率：用户多久会有一次"想要长期沉淀"的思考需求？

**风险信号**：
- "思考型使用" vs "任务型使用"比例可能远低于直觉（参考：Bain 研究，95% 的 LLM 使用是"完成任务"，不是"深度思考"）

## 2. Customer Segments（客户细分）

> 谁是首批用户？细分人群是谁？优先打哪一群？

**已知 ✓**：从 REQUIREMENTS.md "用户假设"段：
- 个人使用为主
- API Key 由用户自配（BYOK 模式）
- 不需要账号体系、不做云同步

**已知 ✓**：从设计系统 + JTBD 分析推断的核心画像：
- **创作者 / 写作者** — 经常需要思考一个主题、写一篇文章
- **深度学习者** — 学习某个领域时希望有"知识树"积累
- **研究者 / 产品经理** — 工作中需要反复深挖某个问题
- **重思考者**（通才）— 喜欢用"思考本身"作为生活的一部分

**假设 ⚠️**：哪个细分群体**最早且最大**愿意用？
- 创作者 → 已有 Roam/Obsidian，迁移成本高
- 深度学习者 → 已习惯 Anki/Notion/Learney 等
- 产品经理 / 研究者 → 已经习惯了各类 AI 工具
- 重思考者 → 体量小但黏性可能最高

**未知 ✗**：
- 这 4 类人群在中国市场的规模分别是多少？
- 哪个细分是"早期采用者"画像？（early adopter 通常 < 主流市场的 16%）
- 优先打**最窄的一群**（beachhead segment），还是**最宽的一群**？

**建议**：
- **优先打"重思考者"**：这群人最痛、最愿意尝试新工具、最不在乎工具是否"主流"
- 其他 3 类作为扩展人群

## 3. Unique Value Proposition（独特价值主张）

> 一句话讲清"我们和 X 有什么不同"？

**已知 ✓**：核心 UVP（从 JTBD 分析提炼）：

> **"AI × 结构化沉淀" 的第三空间**
>
> 不像 ChatGPT 只是聊，不像 Obsidian 只是写 — ThkTree 让 AI 帮你把思考展开、并自动沉淀为可回看可复用的结构化笔记。

**已知 ✓**：差异化要素：
- ✓ 树形对话（vs 单线聊天）— 同一主题下可分叉探索
- ✓ 上下文可控（vs 全量注入）— 用"打磨后的总结"代替 raw history
- ✓ 笔记 ↔ 对话双向流动（vs 工具割裂）
- ✓ 本地优先 + BYOK（vs 云端 SaaS）— 数据自主、隐私安全
- ✓ 设计美学（warm-minimal + 黑金 serif）— 不是"工程师审美"

**假设 ⚠️**：这些差异化要素**用户能感知到**吗？
- 树形 → 必须用过 ChatGPT 觉得"单线不够"才会想要
- 上下文可控 → 是技术细节，普通用户感知不到
- 笔记双向流动 → 必须先有"沉淀习惯"才会感受到价值
- 本地优先 + BYOK → 隐私敏感用户会关心，但占比小
- 设计美学 → 是入场券，不是留存理由

**未知 ✗**：
- 上面 5 个差异化要素，哪个**最强**（用户最买账）？
- "一句话讲清" → 我们目前讲的清不清楚？（"AI × 结构化沉淀的第三空间"已经有点抽象）
- "相对优势" — 用户对比 ChatGPT 时会说"什么是你能做而 ChatGPT 不能的"？

**建议**：
- 测试用更简单的话术：「**树形 AI 对话，每条结论都能一键变笔记**」
- 验证：把这句话给 10 个潜在用户看，看 8/10 能否准确复述

## 4. Solution（解决方案）

> MVP 现在能解决到哪一步？关键假设是什么？

**已知 ✓**：已实现的能力（从 REQUIREMENTS.md §13.1 "已完成"）：
- ✓ 多主题管理 / 树形对话 / 节点重命名 / 节点删除
- ✓ 流式对话 + Stop 控制 + 重新生成
- ✓ 笔记系统（创建、编辑、累积选段、从笔记创建分支）
- ✓ 多 LLM Provider / 自定义 system prompt / 模型选择
- ✓ Face ID 锁 / Vision + AI 绘图分享
- ✓ 全文搜索（已知 feature list）
- ✓ 祖先上下文摘要（stale 机制）

**已知 ✓**：v1 明确**不做**的事：
- ✗ 导出 / 备份 / 导入（用户担心数据丢失！）
- ✗ 账号体系 / 云同步
- ✗ 多厂商 LLM 自动化（已部分实现）
- ✗ Android 端

**假设 ⚠️**：技术方案能解决用户痛点？
- ✓ 树形对话 → 解决"分叉探索"痛点
- ✓ 笔记 ↔ 对话 → 解决"沉淀"痛点
- ⚠️ BYOK → 是**降低 LLM 成本**的好方案，但是**拉高用户使用门槛**的坏方案（必须自己有 API Key）
- ⚠️ Markdown + SQLite → 工程上是亮点，但用户**根本感知不到**

**未知 ✗**：
- Onboarding 流程是什么？（用户进入 App 第一眼看到什么？）
- 首次使用需要多久才能"感受到价值"？（time-to-value 假设 < 5 分钟）
- "BYOK 是壁垒还是负担" — 用户会因为"BYOK 觉得麻烦"而流失吗？

**风险信号**：
- BYOK 门槛可能是**致命假设**：95% 的普通用户不会去 OpenAI 平台充钱、生成 API Key
- "无导出/无云同步"对担心数据丢失的用户是**劝退点**

**已知 ✓**：当前渠道（从仓库推断）：

## 6. Revenue Streams（收入流）

> 怎么赚钱？赚多少？

**已知 ✓**：从 REQUIREMENTS.md + 仓库状态推断 — **ThkTree 目前没有任何商业模式**。
- 无定价页
- 无订阅
- 无广告
- 无打赏
- 用户自付 LLM API 费用（BYOK）

**假设 ⚠️**：商业模式存在吗？
- 假设 A：**纯个人项目 / hobby project**（不是商业产品）→ 那 PMF 体检结论不同
- 假设 B：**未来想商业化** → 必须现在就想清楚
- 假设 C：**开源 + 接赞助 / 卖专业版** → 经典路径但天花板低

**未知 ✗**：核心问题：
- 这是个人作品还是商业产品？（**必须先回答**）
- 如果商业化：免费 / 一次性付费 / 订阅 / Freemium？
- 如果订阅：定价 ¥X/月，覆盖多少用户能养活团队？
- ARPU / LTV / 付费转化率假设是什么？

**风险信号**：
- "先做产品再想商业模式" → 90% 失败案例的共同特征
- BYOK 模式下，**用户每次使用都在给 OpenAI/DeepSeek 付费** → 你无法在用户使用流程里截取价值

## 7. Cost Structure（成本结构）

> 钱花在哪里？固定 vs 变动？

**已知 ✓**（从架构推断）：
- **开发成本**：1 人 Flutter 全栈（推断 = 你自己）
- **LLM API 成本**：用户自付（BYOK）
- **服务器 / 云**：本地优先，无服务器成本 ✓
- **设计成本**：自行设计（已有很高质量的设计系统）
- **运营成本**：未知

**假设 ⚠️**：
- 如果上线后做云同步 → 服务器成本上升
- 如果做分享/导入导出 → 存储成本上升
- 如果做推荐/发现 → 内容审核 + 运营成本

**未知 ✗**：
- 单用户全生命周期成本（cost per user）
- CAC（单用户获取成本）
- 单位经济学（unit economics）：LTV > CAC 吗？

**好消息**：
- BYOK + 本地优先 = **几乎是 0 变动成本**（关键优势）
- 这让 "小而美" 路径成为可能：1000 个付费用户 × ¥30/月 = ¥30000/月，能覆盖 1 人全职

## 9. Unfair Advantage（不公平优势）

> 别人 6 个月能抄走你的什么？抄不走的又是什么？

**已知 ✓**：可能的壁垒：
- **设计美学**（部分可抄）— Cormorant Garamond + warm-minimal 不是独家，但执行得不错

**假设 ⚠️**：
- 树形对话本身 → 6 周可抄

**未知 ✗**：
- 真正**不可抄**的壁垒是什么？
  - 数据？→ 你还没有用户数据
  - 网络效应？→ 还没有
  - 品牌？→ 还没有
  - 社区？→ 还没有

- 当前阶段（Pre-PMF）：**没有任何 moat**
- moat 是 PMF 之后的事，不是 PMF 之前的事
- 不要花时间想"怎么防抄"，要花时间想"怎么证明有人要"

## 🎯 11. Pre-PMF 阶段必须做的 3 件事（按优先级）

### 第 1 件事：**和 50 个潜在用户深聊**（最优先，2 周内）

| 项 | 建议 |
|----|------|
| **目标** | 验证 §1 Problem 是否真痛 + 验证 §3 UVP 是否讲清 |
| **方法** | 1v1 视频访谈（30 分钟），每次问 5 个问题 |
| **关键问题** | 见下方 §11.1 |
| **来源** | 知乎深度话题、即刻、V2EX、Twitter、小红书"深度思考"tag |
| **产出** | 50 份访谈记录 + 痛点强度评分（5 分制） |
| **成功标准** | 30/50 的人说"我经常遇到这个问题"，20/50 的人说"我愿意试试" |
| **失败信号** | 50 人聊完都说"听起来不错，但我应该不会用" |

#### 11.1 关键访谈问题

```
1. 上周/上月，你什么时候会有"想要深度思考一个问题"的时刻？
   （如果对方想不起来 → 痛点不够频次）

2. 那次思考你会怎么做？会用哪些工具？最后结果是什么？
   （如果对方已有现成工作流 → 切换成本高）

3. 如果有一天 ChatGPT 关了、Claude 关了，你会用什么替代？
   （探知 AI 依赖度）

4. 你现在用什么工具沉淀"思考结果"？多久会回看一次？
   （探知沉淀习惯）

5. 看到这句话「树形 AI 对话，每条结论都能一键变笔记」你第一反应是什么？
   （探知 UVP 是否讲清）
```

### 第 2 件事：**做一个能跑的 MVP Landing Page + 等待名单**（2 周内）

| 项 | 建议 |
|----|------|
| **目标** | 验证"看到产品描述后是否愿意留邮箱" |
| **工具** | Carrd.co / Framer / Vercel / Notion 自带 |
| **关键内容** | 一句话 UVP + 3 张截图 + 1 个 CTA（留邮箱） |
| **成功标准** | 1000 个目标用户曝光 → 50+ 邮箱注册 |
| **失败信号** | 1000 曝光 < 20 邮箱 → UVP 没讲清或目标用户没找对 |

### 第 3 件事：**小范围 TestFlight 内测（20-50 人）**（3-4 周内）

| 项 | 建议 |
|----|------|
| **目标** | 拿到真实的"使用行为数据" |
| **关键埋点** | 首条对话完成率、D7 留存、笔记创建率 |
| **特别关注** | BYOK 流失率 — 用户在配 Key 这一步流失多少？ |
| **成功标准** | D7 留存 ≥40% + 30% 用户在第一周创建笔记 |
| **失败信号** | D7 留存 < 20% 或 BYOK 流失率 > 70% |

## 🚫 12. Pre-PMF 阶段不要做的事（重要！）

| ✗ 不要做 | 原因 |
|---------|------|
| **不要继续加新 feature** | "觉得还差一个功能" 是 PMF 阶段最大的陷阱 |
| **不要重做设计** | 设计已经是 9/10，不是当前瓶颈 |
| **不要想变现** | 没有用户时谈变现 = 在 0 上乘 0 |
| **不要投广告** | CAC 会远超 LTV |
| **不要做品牌官网** | 现在做品牌是给 0 个人看 |
| **不要担心"被抄"** | 现在担心被抄 = 高估自己的价值 |
| **不要优化性能** | 性能不是当前瓶颈 |
| **不要扩展到 Android** | 主线没验证前扩展是分散精力 |

**唯一要做的事**：
> **用最少的代码改动，配合 §11 的 3 件事，拿到用户行为证据。**

## 💡 13. 关于 "BYOK 是不是好策略"（专门讨论）

这是 ThkTree 战略上**最值得重新审视**的决策。

### 13.1 BYOK 的好处（你当初选它的原因）

- ✓ 零 LLM 成本（你不用付 DeepSeek/OpenAI 钱）
- ✓ 隐私强（用户数据只给 LLM Provider，不给你）
- ✓ 用户对成本有感（自己用多少自己付）
- ✓ 无需计费系统、无需发票、无需合规

### 13.2 BYOK 的代价（可能被低估）

- ✗ **入门门槛高**：95% 用户**不会**去 DeepSeek 平台充钱生成 Key
- ✗ **首次体验断裂**：用户下载 → 必须配 Key → 必须充钱 → 才能体验核心功能
- ✗ **失去使用数据**：你不知道用户用了多少次、花了多少钱（数据是 PMF 信号！）
- ✗ **没法做"先免费体验 N 次"**：传统 freemium 模式失效

### 13.3 替代方案对比

| 方案 | 门槛 | LLM 成本 | 数据可见性 | 商业模式 |
|------|------|---------|-----------|---------|
| **当前：BYOK** | 高 | 用户付 | ✗ 无 | 不明 |
| **方案 A：你付费 + 有广告** | 低 | 你付 | ✓ 有 | 广告 |
| **方案 B：你付费 + 免费 N 次 + 订阅** | 低 | 你付 | ✓ 有 | 订阅 |
| **方案 C：你付费 + 免费 + 付费解锁高级 feature** | 低 | 你付 | ✓ 有 | 增值 |
| **方案 D：BYOK + 首次免费试用 5 次** | 中 | 混合 | ✓ 有 | 不明 |

**建议**：认真考虑 **方案 D（BYOK + 首次免费试用 5 次）** — 兼顾 BYOK 的隐私优势，又解决"首次体验断裂"问题。

如果想再进一步，可以做 **方案 C（你付少量 LLM 成本 + 订阅解锁）** — 用你付的成本换用户行为数据，再用订阅变现。
