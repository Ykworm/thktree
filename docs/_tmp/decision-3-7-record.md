## 决策 #3：BYOK 还是混合模式？

### Frame（核心问题）

用户必须自己配 API Key 才能用 ThkTree，还是你承担一部分 LLM 成本？

### Diverge（4 个选项）

| 选项 | 入门门槛 | LLM 成本 | 用户行为数据 | 商业模式 | 推荐度 |
|------|---------|---------|------------|---------|-------|
| **A. 纯 BYOK** | 极高 | 用户付 | ✗ 无 | 不明 | ❌ |
| **B. BYOK + 前 5 次你付费** | 中 | 你付 5 次/用户 | ✓ 有（最关键的 5 次数据） | 不明 | ⭐⭐⭐⭐⭐ |
| **C. 你付费 + 免费 5 次 + 然后订阅解锁** | 中 | 你付 | ✓ 有 | 订阅 | ⭐⭐⭐⭐ |
| **D. 你付费 + 完整免费 + 广告** | 低 | 你付 | ✓ 有 | 广告 | ⭐⭐ |

### Provoke（关键反对意见）

**对 A 的反对（最强烈）**：
- 95% 的潜在用户在"下载 → 配 Key"这一步流失
- 你永远不知道他们试过、喜欢不喜欢
- "配 Key 失败" = 用户根本没机会体验你的核心 job

**对 C 的反对**：
- 订阅在阶段 1（个人项目）会增加摩擦
- 订阅 = 必须做支付集成、做退款逻辑、做订阅管理 UI
- 这些都是工作量，不是 PMF 信号

**对 D 的反对**：
- 广告会让"重思考者"瞬间离开
- 与 ThkTree 的 warm-minimal 设计哲学冲突

### Converge（强推荐 + 理由）

**强烈推荐选项 B（BYOK + 前 5 次你付费）**：

**精妙之处**：
- 前 5 次你付费 → 用户能完整体验核心 job
- 5 次后引导用户配自己的 Key → 不再有持续成本
- **你拿到了最关键的 5 次使用数据**（= PMF 信号）
- BYOK 的隐私优势保留

**5 次免费试用的额外好处**：
- 用户有了"我用过、感觉不错"的心智锚点 → 配 Key 时阻力小
- 用户的第一次"周末深度会话"几乎肯定在前 5 次 → 触发北极星指标

**5 次免费试用的成本估算**：
- 假设 1 个深度会话 = 20 轮对话 × 2000 tokens/轮 = 40k tokens
- DeepSeek V4 价格：约 ¥1/百万 input tokens
- 单次会话成本 ≈ ¥0.08
- 5 次免费 ≈ ¥0.4/用户
- 1000 个用户用完 5 次 ≈ ¥400 总成本
- **几乎可以忽略的成本，换来最关键的用户行为数据**

### ⚠️ 用户实际拍板：A（纯 BYOK）

**尊重用户决策**。这意味着：

**用户接受的代价**：
- 95% 的潜在用户在"下载 → 配 Key"这一步流失
- 你不知道流失用户的真实反馈
- Pre-PMF 阶段的用户基数会非常小

**用户保留的优势**：
- 隐私优势最强（用户数据完全不到你这里）
- 产品形态最简（不需要做"5 次试用"逻辑、不需要管理赠送配额）
- 与 ThkTree 现有架构零冲突（零代码改动）
- 与"重思考者"画像匹配（这群人愿意为隐私付代价）

**关键风险（必须监控）**：
- 如果 §11 的 50 人访谈完成率 < 30% → 必须重新评估"BYOK 是不是主因"
- 如果用户反馈反复出现"配 Key 太麻烦" → 触发重新评估
- 第一次 re-evaluation 时点：2026-08-31

### ✅ 立刻动作

1. **不**加 5 次免费试用流程（保持现状）
2. 但加一个**配 Key 引导流程优化**：在配 Key 失败时给更友好的引导
3. 准备一个"邀请制"机制：通过朋友推荐才能下载 → 绕过"配 Key 流失"

## 决策 #4：一句话 UVP

### Frame（核心问题）

用户看到一句话，能不能立刻知道"这是不是为我做的"？

### Diverge（4 个候选 UVP）

| 候选 | 评测 |
|------|------|
| ❌ "AI × 结构化沉淀的第三空间" | 太抽象，普通人听不懂 |
| ❌ "树形 AI 对话笔记 App" | 像功能描述，不是价值主张 |
| ❌ "AI 帮你思考" | 太通用，谁都能说 |
| ⭐ "和 AI 一起，慢慢想" | 短、有节奏感、对重思考者有吸引力 |
| ⭐⭐⭐ "树形 AI 对话，每条结论都能一键变笔记" | 功能具体、价值清晰、动词明确 |

### Provoke（关键反对意见）

**对 "AI × 结构化沉淀的第三空间" 的反对**：
- 这是**给我们自己**看的话术，不是给用户看
- 普通用户读完不知道你在说什么

**对 "树形 AI 对话笔记 App" 的反对**：
- 像功能描述，没有价值主张
- "App" 一词显得过时（现在都是 App / 网页 / 命令行）

**对 "AI 帮你思考" 的反对**：
- 太通用，ChatGPT、Claude、Notion AI 都能用
- 没有差异化

### Converge（强推荐 + 理由）

**强烈推荐：双轨制**

| 场景 | UVP | 理由 |
|------|-----|------|
| **对外（landing page / 社交媒体 / 朋友推荐）** | **"和 AI 一起，慢慢想"** | 打动人心；与"重思考者"画像强匹配 |
| **对内 / 转化场景（应用商店描述 / 功能介绍 / README）** | **"树形 AI 对话，每条结论都能一键变笔记"** | 说清功能；动词明确；SEO 友好 |

**关键理由**：
- 决策 #2 锁定了"重思考者"——这群人最反感"高效 / 自动化 / 一键生成"这种话术
- "慢慢想" 三个字是 ThkTree 真正的差异化（vs ChatGPT 的"快速回答"）
- 双轨制让品牌感 + 转化率兼顾

### ✅ 立刻动作

1. README 顶部 hero 区：用 "和 AI 一起，慢慢想"
2. README 副标题：用 "树形 AI 对话，每条结论都能一键变笔记"
3. Landing Page（同 README 结构）
4. 应用商店描述：用功能版 UVP
5. 朋友圈 / 微博推广：用品牌版 UVP

## 决策 #5：北极星指标

### Frame（核心问题）

用哪个数字判断 ThkTree 是不是在被正确使用？

### Diverge（5 个候选指标）

| 候选 | 衡量什么 | 优势 | 问题 |
|------|---------|------|------|
| ❌ DAU/MAU | 粘性 | 通用 | 重思考者使用频率本来就不高，会被低估 |
| ❌ 总对话轮数 | 活跃度 | 简单 | 不区分"有效思考"和"瞎聊" |
| ⭐ 周笔记创建数 | 是否真的在"沉淀认知" | 完美对应核心 job | 只反映"沉淀"维度 |
| ⭐ 周树形分支数 | 是否真的在"分叉探索" | 完美对应差异化 | 只反映"差异化"维度 |
| ⭐⭐⭐ **"周末深度会话数"** | 是否真的在"深度思考" | 完美对应"重思考者"画像 | 需要埋点统计 |

### Provoke（关键反对意见）

**对 DAU/MAU 的反对**：
- 重思考者"按周"使用，不是"按天"使用
- DAU/MAU 会系统性低估 ThkTree 的真实价值

**对总对话轮数的反对**：
- 不区分"有效思考"和"瞎聊"
- ChatGPT 的总消息数没有意义

### Converge（强推荐 + 理由）

**强烈推荐："周末深度会话数"**（每周单次 > 30 分钟的会话数）

**关键理由**：
1. **最直接反映"重思考者是否真的在用"**：这群人的特征就是"深度会话 > 30 分钟"
2. **ChatGPT / Claude 没有这个指标**（他们更看重总消息数）→ 这是 ThkTree 的专属护城河指标
3. **阶段 1（个人项目）只要这个数字在涨，就说明 PMF 信号在增强**

**辅助指标（用于交叉验证）**：
- 周笔记创建数（验证"沉淀"维度）
- 周树形分支数（验证"分叉探索"差异化）
- D7 / D30 留存（验证粘性）

**核心 vs 辅助的关系**：
- 1 个北极星 + 3 个辅助 = 健康
- 辅助涨但北极星不涨 = 假的 PMF 信号
- 北极星涨但辅助不涨 = 用户在用但没形成习惯，需要补

### ✅ 立刻动作

1. 在 App 内做埋点：记录每次会话时长、会话内分支创建数、笔记创建数
2. 在 Settings 页加一个"个人统计"模块，让用户看到自己的"周末深度会话数"
3. 阶段 1 内手动追踪，不需要复杂的 BI 平台

## 决策 #6：商业模式

### Frame（核心问题）

未来怎么变现？

### Converge（强推荐）

**强烈推荐：阶段 1 不决定商业模式**

**理由**：
- 阶段 1（个人项目 + 3-6 个月）目标是验证 PMF，不是变现
- 没有用户数据时谈变现 = 在 0 上乘 0
- 决策 #1 已锁定"分阶段"，所以商业模式推到阶段 2 再决定

### 但阶段 2 的候选要心里有数

| 候选 | 优势 | 风险 | 适合人群 |
|------|------|------|---------|
| **订阅**（¥30/月） | 持续收入、可预期 | 需要做支付集成 | 高频使用用户 |
| **买断**（¥98 一次性） | 用户决策简单 | 没有持续收入 | 低频但深度的用户 |
| **Freemium**（免费 N 个主题 + 付费解锁） | 转化路径清晰 | 需要限制功能 | 大众市场 |
| **赞助 / 打赏** | 无压力 | 收入不可预期 | 个人项目 / 公益心态 |
| **不开源 + 不变现** | 0 压力 | 长期无资金支持 | 纯作品 / hobby |

**推荐阶段 2 的判断标准**：
- 如果 D7 留存 ≥ 40% → 考虑订阅（用户已经形成习惯）
- 如果用户嫌订阅贵 → 考虑买断
- 如果用户根本不愿付费 → 考虑赞助 / 打赏

### ⚠️ 用户实际拍板：阶段 1 暂缓，阶段 2 根据"灵感"选择

**"灵感"这个词很关键** — 表达了用户**不被数据完全绑架**的态度。这与 ThkTree 的设计哲学完全一致。

**风险记录**：
- 不预设商业模式可能导致阶段 2 决策时缺乏框架
- 缓解措施：阶段 1 收集所有用户反馈中关于"愿不愿意付费 / 付多少"的语言信号
- 阶段 2 决策时不再用"数据矩阵"硬选，而是用"哪个方向最有灵感"选

## 决策 #7：6 个月目标

### Frame（核心问题）

到 2026-12-24，ThkTree 应该达到什么状态？

### Diverge（3 个目标级别）

| 级别 | 标准 | 触发下一步 |
|------|------|----------|
| **C 级（失败红线）** | 没有用户、没有反馈 | 退回"纯个人作品"（决策 #1 选项 A） |
| **B 级（继续观察）** | 50 人访谈完成 + 30 邮箱 + 10 人 TestFlight + D7 留存 < 40% | 继续阶段 1，再做 3 个月 |
| **A 级（PMF 信号）** | 50 人访谈完成 + 50 邮箱 + 20 人 TestFlight + D7 留存 ≥ 40% + 30% 用户第一周创建笔记 | 进入阶段 2（商业化） |

### Provoke（关键反对意见）

**对 A 级的反对**：
- A 级标准看起来不高，但对一个 Pre-PMF 产品来说：
  - D7 留存 ≥ 40% 是 Sean Ellis PMF 测试的行业基准
  - 30% 用户第一周创建笔记意味着核心 job 被满足
- 这两个数字都达到 = 真实 PMF 信号

**对 B 级的反对**：
- B 级容易变成"温水煮青蛙"——3 个月又 3 个月
- 必须给 B 级设定严格的 re-evaluation 时点：3 个月后必须做决定（A 还是 C）

### Converge（强推荐 + 理由）

**强烈推荐：**

- **A 级作为目标**（成功标准）
- **B 级作为兜底**（继续观察）
- **C 级作为失败红线**（强制收尾）

**6 个月里程碑拆解**：

| 时间点 | 里程碑 |
|--------|--------|
| **6 月底**（现在） | 决策拍板 + 启动 §11 的 3 件事 |
| **7 月底** | 完成 20 人访谈 + Landing Page 上线 + 50 邮箱 |
| **8 月底** | 完成 50 人访谈 + TestFlight 开始招募 |
| **9 月底** | TestFlight 内 20+ 用户 + D7 留存数据初步可见 |
| **10 月底** | 中期评估：调整 §11 的执行策略 |
| **11 月底** | 完整数据回流：北极星指标趋势 + 留存漏斗 + 用户反馈 |
| **12 月底** | 最终评估：A / B / C 三选一 |

### ⚠️ 用户实际拍板：A 为目标，B 为验收

**精明的决策**：
- A 级作为"理想目标" — 知道自己想要什么
- B 级作为"验收标准" — 防止 A 达不到时自我欺骗

**含义**：
- 如果 2026-12-31 达到 A 级 → 进入阶段 2（商业化）
- 如果 2026-12-31 在 A-B 之间 → 继续阶段 1，再做 3 个月
- 如果 2026-12-31 低于 B 级 → 重新评估方向（可能退回纯个人作品）
