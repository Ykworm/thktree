# 搜索功能设计文档

本文件定义笔记+对话全文搜索功能的技术设计。产品需求见 REQUIREMENTS.md，存储格式权威见 docs/storage-format.md。

---

## 1. 目标与非目标

### 目标

- 提供跨全主题的笔记+对话全文搜索
- 搜索结果按 BM25 相关性排序（同分按时间降序）
- 搜索结果高亮显示匹配片段
- 索引异常不 crash，用户可手动修复

### 非目标

- Phase 1 不做语义搜索（Core ML embedding 方案另案评估）
- 不做搜索结果分类标签页切换（采用混合列表 + 来源标记）
- 不替换 Markdown 文件为纯 SQLite 存储（Markdown 始终是真相源）

## 2. 架构总览

```
┌────────────────────────────────────────────┐
│                    UI 层                     │
│  CupertinoTabBar 新增「搜索」Tab              │
│  └── SearchScreen                           │
│      ├── CupertinoSearchTextField           │
│      └── 混合结果列表（笔记 + 对话）           │
├────────────────────────────────────────────┤
│                  数据层                      │
│  SearchService                              │
│  ├── search(query) → List<SearchResult>     │
│  ├── upsertNote(...) / upsertMessage(...)   │
│  └── rebuildAll()  从 .md 全量重建索引       │
├────────────────────────────────────────────┤
│                 存储层                       │
│  Markdown 文件 ←→ SQLite FTS5 search_index  │
│  (真相源)          (搜索加速层，可重建)        │
└────────────────────────────────────────────┘
```

### 核心原则

- **Markdown 是真相源**：所有笔记/对话正文存储在 `.md` 文件中
- **SQLite FTS5 是搜索加速层**：提供全文检索能力，可随时删除并从 `.md` 重建
- **先文件后索引**：写入时优先保证 `.md` 落盘成功，索引更新失败不阻断写入

## 3. FTS5 表结构

```sql
CREATE VIRTUAL TABLE search_index USING fts5(
  entityType,    -- 'note' | 'message'
  entityId,      -- noteId | msgId
  themeId,
  themeTitle,    -- 主题名（用于搜索结果展示）
  entityTitle,   -- 笔记标题或对话节点标题
  content,       -- 完整正文，FTS5 内部存储（支持 snippet()）
  updatedAt      -- 排序辅助字段（非索引列，unindexed）
);
```

### 字段说明

| 字段 | 用途 |
|------|------|
| entityType | 区分笔记/对话，UI 展示来源标记 |
| entityId | 跳转定位（笔记 → 打开笔记、消息 → 跳对话节点） |
| themeId / themeTitle | 显示所属主题，跨主题搜索时提供上下文 |
| entityTitle | 列表展示标题 |
| content | **完整正文**——FTS5 内部存储原文，`snippet()` 用其生成高亮片段 |
| updatedAt | 辅助排序，同 BM25 分时按时间降序 |

### Content 双写的必要性

FTS5 的 `snippet()` 函数只能从 FTS5 内部存储读取原文——它不读 `.md` 文件。因此 content 字段必须在 FTS5 中存一份完整原文。

这不是设计冗余，而是 `snippet()` 功能的硬约束。且笔记/对话的文本量本身不大，这个代价可以接受。

## 4. 数据同步策略

### 4.1 增量更新（常态路径）

#### 笔记

```
笔记保存/编辑
  → writeAsString(.tmp) + rename  ← 原子写 .md ✓
  → searchIndex.upsert(...)       ← 更新 FTS5（unawaited，失败不影响写入）
```

#### 对话消息

```
流式过程（appendDelta）
  → 逐 token 写 session.md（原子写）
  → 不碰 FTS5                          ← 关键：不在流式过程中更新索引

流结束（finishAssistant）
  → _atomicWriteString 完成 session.md ✓
  → searchIndex.upsert(...)  ← 此时才更新 FTS5（unawaited）
```

**设计理由**：流式过程中逐 token 更新 FTS5 会严重拖慢性能（N 次 INSERT）。索引更新只在消息完整落盘后执行一次。

### 4.2 全量重建（兜底路径）

```dart
Future<void> rebuildSearchIndex() async {
  await db.execute('DELETE FROM search_index');   // 清空
  await db.execute('BEGIN TRANSACTION');

  for (var i = 0; i < records.length; i++) {
    await db.insert('search_index', records[i]);
    if (i % 50 == 0) {                             // 分批提交
      await db.execute('COMMIT');
      await Future.delayed(Duration.zero);          // 让出事件循环
      await db.execute('BEGIN TRANSACTION');
    }
  }
  await db.execute('COMMIT');
}
```

**触发时机**：
- 仅当 `search_index` 表为空时自动触发（首次使用场景）
- 用户在弹窗中主动点击「重建索引」（异常修复场景）

**性能保障**：
- 每 50 条 commit 一次，中间 `Future.delayed(Duration.zero)` 让 Flutter 处理 UI 事件
- 避免阻塞用户交互

### 4.3 扫描规则

```dart
// 笔记：遍历 themes/{themeId}/notes/{noteId}.md
// 对话：遍历 themes/{themeId}/nodes/{nodeId}/session.md

// 跳过规则：
//   1. 带有 <!-- streaming --> 标记的 session.md（消息未完成）
//   2. 解析失败的记录：YAML 降级处理，不 skip
```

## 5. 搜索查询

### 5.1 查询语句

```sql
SELECT
  entityType,
  entityId,
  themeId,
  themeTitle,
  entityTitle,
  snippet(search_index, 1, '<b>', '</b>', '...', 40) AS snippet,
  updatedAt,
  bm25(search_index, 0.0, 1.0, 0.0, 0.0, 0.5, 5.0) AS rank
FROM search_index
WHERE search_index MATCH :query
ORDER BY rank ASC, updatedAt DESC
LIMIT 50;
```

### 5.2 排序规则

1. **BM25 相关性**优先
2. 同分按 **updatedAt 降序**（最新的在前）

### 5.3 交互模式

- 用户输入时显示建议（防抖 300ms）
- 点击搜索按钮或键盘确认展示完整结果
- 结果列表每条显示：
  - 标题
  - 匹配片段（带高亮 `**...**`）
  - 来源标记（📝笔记 / 💬对话）
  - 所属主题名
- 点击条目跳转到对应来源

## 6. 异常处理

### 核心约束

| 约束 | 说明 |
|------|------|
| **不 crash** | 所有 FTS5 操作 try/catch，异常时降级 |
| **不阻断写入** | 索引失败不影响 `.md` 写入 |
| **不自动重建** | 发现问题时提示用户，不静默执行耗时操作 |
| **可恢复** | 用户始终能通过弹窗中的按钮触发修复 |

### 6.1 场景1：写入时索引更新失败

```
search_index upsert 失败
  → ARMS 上报 search_index_upsert_failed（entityType, entityId, errorMessage）
  → 静默跳过，不抛异常，不提示用户
  → .md 文件已正常保存
```

### 6.2 场景2：搜索时 FTS5 异常

```
弹出 CupertinoAlertDialog：
┌─────────────────────────────────────┐
│         搜索服务异常                  │
│                                      │
│  搜索功能暂时不可用，需要重建搜索      │
│  索引来恢复。您的笔记和对话内容不会     │
│  受到影响。                          │
│                                      │
│            [取消]  [重建索引]         │
└─────────────────────────────────────┘

用户点击 [重建索引]
  → 显示 CupertinoActivityIndicator + "正在重建索引..."
  → rebuildSearchIndex()
  → 成功：关闭弹窗，刷新搜索结果
  → 失败：进入场景4

用户点击 [取消]
  → 返回搜索页（空白状态）
```

### 6.3 场景3：重建索引完成（含降级记录）

```
┌─────────────────────────────────────┐
│         索引重建完成                  │
│                                      │
│  搜索功能已恢复，您的笔记和对话内容     │
│  均完整保存。                        │
│                                      │
│  （仅当 N > 0 时显示）               │
│  有 N 条记录因格式兼容性问题暂未纳入    │
│  搜索范围，不影响内容的正常使用。       │
│                                      │
│              [知道了]                │
└─────────────────────────────────────┘
```

### 6.4 场景4：重建索引彻底失败

```
磁盘满 / SQLite 损坏（重试无意义）：
┌─────────────────────────────────────┐
│         无法重建索引                  │
│                                      │
│  搜索功能暂时不可用。您的笔记和对话     │
│  内容不受影响，仍可正常浏览。          │
│                                      │
│  请检查设备存储空间后重试。            │
│                                      │
│            [稍后重试]  [知道了]       │
└─────────────────────────────────────┘
```

### 6.5 异常提示文案原则

**每次异常提示都明确强调"内容安全"**，消除用户的恐慌心理：
- "笔记和对话内容不会受到影响"
- "内容均完整保存"
- "不影响内容的正常使用"

### 6.6 ARMS 上报事件

| 事件 | 携带数据 |
|------|---------|
| `search_index_upsert_failed` | entityType, entityId, errorMessage |
| `search_query_failed` | query, errorMessage |
| `search_rebuild_failed` | recordCount, errorMessage |

### 6.7 .md 解析降级处理

```
YAML frontmatter 解析失败
  → 不 skip，用文件名当标题、父目录名当 themeTitle
  → 内容照常索引

文件读取失败（磁盘满等）
  → skip 当前文件，继续下一条
  → ARMS 上报（path + error）
```

## 8. 实现任务分解

### 任务1：FTS5 基础设施

- 创建 `search_index` 虚拟表
- 实现 `SearchService`，封装 upsert / search / rebuildAll
- 实现分批处理 + 事件循环让出

### 任务2：增量同步

- 笔记保存/编辑后触发 `searchIndex.upsert()`
- `finishAssistant` 后触发 `searchIndex.upsert()`
- 均使用 `unawaited`，不阻塞主流程

### 任务3：全量重建

- 实现 `rebuildSearchIndex()`（扫描所有 .md → FTS5）
- 仅当表为空时自动触发
- YAML 降级处理

### 任务4：搜索 UI

- 新增搜索 Tab（CupertinoTabBar）
- `SearchScreen` + `SearchTextField`
- 混合结果列表
- 点击跳转逻辑

### 任务5：异常处理

- 各场景的 try/catch + CupertinoAlertDialog
- ARMS 异常上报
- 安心文案实现

### 任务6：国际化

- 搜索相关字符串加入 l10n
