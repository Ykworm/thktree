# 测试数据：主题 + 文章（话题库 seed）

> **用途**：`TREE-1`（话题库 3×3×3×4 树生成 + 笔记写入）消费这套数据。
> 它是 `integration_test/_support/topic_library.dart` 的**人话可读镜像**——后者是运行时真源（Dart 常量），本文件方便人和 LLM 审阅/迭代内容。
> **改内容时两处同步**：动了本文件，也要改 `topic_library.dart`；反之亦然。后续若想单一真源，可让 `topic_library.dart` 解析本文件（待定）。
>
> **结构**：3 主题 × 每主题 3 个 root chat × 每 root 一条分支链。完整 fixture 定义到 **3×3×3×4**（3 主题 / 3 root / 最多 3 层分支 / 最深 4 层）。
> **深度约束**：产品硬上限 4 层（`kMaxNodeDepth=4`）。`MAX_DEPTH` 默认 2（root→child），可用 env `MAX_THEMES`/`MAX_ROOTS`/`MAX_DEPTH` 覆盖。
> 每条分支的 `prompt` = 发给 LLM 的「文章/问题」；`expectedReply` = 期望回复摘要（用于校验「无 LLM error / 回复非空」，不逐字比对）。

## 备注

- **BC-1..BC-13（分支创建）不消费本数据**：它们用硬编码 prompt「请用一句话介绍你自己」，与本主题库无关。只有 `TREE-1` 跑这套 3 主题 × 3 root × 分支链。
- **真实 LLM**：TREE-1 默认走真实 LLM（`--dart-define-from-file`）；设 `MOCK_LLM=true` 可用 fake key 跑（只验结构/持久化，不验回复质量）。
- **校验**：每主题 root 数 = `MAX_ROOTS`(3)；派生节点数 = `MAX_ROOTS × MAX_DEPTH`；每父节点恰好 1 子节点；所有 session 无 LLM error；每 root 至少 1 条 assistant `done` 消息；总 chat 数 = `MAX_THEMES × MAX_ROOTS × (1 + MAX_DEPTH)`。
